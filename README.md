# TZ Linux 探针面板

一个轻量、自托管的 Linux 服务器监控面板。面板和探针均为单文件程序，无需外部数据库。

## 功能

- 服务器名称、IP、运行时间、CPU、内存、存储实时状态
- 实时上传/下载速度（M/s）、今日和昨日流量汇总、各节点累计上传/下载流量
- 全局流量汇总、在线/离线状态
- 服务器编辑、删除、自定义排序（数字越大越靠前）
- 自定义分组，同一服务器可同时属于多个分组
- 探针一键安装、面板内一键升级
- 所有节点共用一条安装命令，首次上报自动注册
- amd64、arm64、armv7 Linux 支持
- 管理接口令牌保护、探针独立随机令牌
- 登录后可修改管理令牌，修改结果持久保存
- 管理令牌只要求非空，不限制长度、复杂度，支持中文、空格和符号
- 分组编辑支持服务器多选和一键全选
- 运行时间按整天显示（不足一天显示 0 天），四列流量位于运行时间之前
- 离线节点整行灰显；手机端自动切换服务器卡片，支持直接编辑、升级、删除

## 部署面板

### 一键安装（无需 Docker）

使用 root 用户运行：

```bash
curl -fsSL https://raw.githubusercontent.com/panhui/tz/main/scripts/install-panel.sh | bash
```

普通用户可以运行：

```bash
curl -fsSL https://raw.githubusercontent.com/panhui/tz/main/scripts/install-panel.sh | sudo bash
```

安装完成后会显示访问地址和自动生成的管理令牌。请保存管理令牌，并在服务器防火墙中放行 TCP 876 端口。

需要重新查看当前管理令牌时，在面板服务器运行：

```bash
grep '^TZ_ADMIN_TOKEN=' /etc/tz-panel.env
```

令牌可能以双引号包裹保存，最外层引号不是令牌内容。升级会保留当前令牌。

### Docker Compose（推荐）

```bash
git clone https://github.com/panhui/tz.git
cd tz
# 请先修改 docker-compose.yml 中的 TZ_ADMIN_TOKEN
docker compose up -d
```

打开 `http://服务器IP:876`，输入你设置的管理令牌。

### 直接运行

从 Releases 下载对应架构的 `tz-panel-linux-*`，然后运行：

```bash
chmod +x tz-panel-linux-amd64
TZ_ADMIN_TOKEN='替换为高强度令牌' TZ_LISTEN=':876' TZ_DATA='./data/data.json' ./tz-panel-linux-amd64
```

生产环境建议在面板前配置 HTTPS 反向代理。

## 升级面板与修改端口

重新执行一键安装命令即可升级。新安装默认使用 **876**；已有安装保留 `/etc/tz-panel.env` 中的端口，避免现有探针断连。显式切换到 876：

```bash
curl -fsSL https://raw.githubusercontent.com/panhui/tz/main/scripts/install-panel.sh | bash -s -- --port 876
```

切换前请放行 TCP 876。切换后访问 `http://服务器IP:876`，在每台节点重新执行新面板中显示的安装命令，以更新上报地址；节点 ID 会保留。通过反向代理接入且外部地址不变时，只需更新代理的后端端口。

直接运行程序时，Linux 的低端口需要 root 权限或 `CAP_NET_BIND_SERVICE`；一键安装已为服务配置该权限，Docker Compose 已配置容器内低端口监听。

## 今日与昨日流量统计

列表显示每台服务器的「今日上传」「今日下载」。顶部使用三张卡片：实时上传/下载速度、今日上传/下载总流量、昨日上传/下载总流量。实时速度卡片底部同时显示当前范围内的累计上传和下载总流量。三张卡片均随分组切换：选择「全部服务器」时汇总全部节点，选择分组时只统计该分组。速度只统计在线节点，今日、昨日和累计流量包含该分组的离线节点，同一节点只计一次。左侧分组栏分割线下显示当前范围的在线、离线数量。按北京时间（UTC+8）每天 00:00 将今日数据结转到昨日，面板重启后保留。

统计从首次上报建立基线开始，不把节点此前累计流量算入今日。v0.9.0 修复了上报延迟被误判为重启、计数下降后重复累加历史流量的问题。建议同步升级探针：新版上报启动标识、网卡名称及接口编号，重启或网卡集合变化时重新建立基线，跳过无法确认的那一次增量。暂时下降的计数保留原高水位，恢复后只统计超过高水位的增量；无法识别的网卡计数重置可能少计，直到计数超过原高水位或启动/网卡标识变化。

跨零点的上报间隔按时间比例分配到今日和昨日，长时间断连跨日时属于估算；断连期间丢失的计数无法恢复。升级保留已有数据，不自动清空可能已受旧版 bug 影响的统计；已经多计的流量无法从现有快照准确还原。没有保存的昨日历史显示为 0，从新版运行后的零点开始正常结转。

## 安装探针

进入面板，点击“安装探针”，复制弹窗中的通用安装命令，在所有目标 Linux 服务器以 root 用户执行即可。每台服务器会生成自己的节点 ID，首次上报后自动出现在列表中，无需提前添加服务器。

## 华为云 DDNS 定时解析

点击面板顶部的 **DDNS**。先填写华为云的 Access Key Id 和 Secret Access Key，再新建解析任务：填写完整解析域名、A 记录的 IPv4 目标或 CNAME 目标域名，并选择首次执行的北京时间。可设为仅一次、每天、每周或每月；任务也可立即执行，手动执行不改变原定计划。支持编辑、暂停、开启、删除和查看执行日志。日志显示执行时间、原解析值、新解析值和执行结果。删除任务不会删除华为云上的 DNS 记录。

面板会自动在此账号的公网域名中查找所属域名；若记录不存在会创建，若目标已相同则不重复修改。请确保密钥具备 DNS 公网域名和记录集的查询、创建、修改权限。密钥保存在面板服务器的 `TZ_DATA` 数据文件（文件权限 `0600`）中，不会回显到浏览器或写入执行日志。建议为此用途创建最小权限的独立凭据，并使用 HTTPS 访问面板。

## 升级探针

服务器行的操作区显示编辑和三点按钮。点击三点可选择升级探针、重启、关机、清空流量或删除服务器。列表增加「前天上传」「前天下载」，支持点击排序和在列设置里显示、隐藏、调整顺序。

「清空流量」需确认后执行，只清空该节点的今日、昨日、前天及累计上传/下载，不影响其他节点、分组、备注和在线状态。结果持久保存，面板重启后不会恢复。节点下一次上报先建立新基线（离线节点重新上线时同样如此），之后才统计新增流量；清空后累计流量表示从新基线开始的流量，节点重启不会清掉这个累计值。

点击服务器行末尾的三点菜单，选择“升级探针”。在线探针会在下一次心跳收到升级指令，从最新 GitHub Release 下载新版本并自动重启。

列表顶部的“全部升级”会给面板中的所有节点排队升级，包括离线节点；离线节点重新上线后执行。

## 远程重启和关机

服务器列表的“操作”列提供“重启”和“关机”按钮。确认后，面板只向当前在线节点下发预定义的重启或关机指令，探针在下一次心跳领取并通过 systemd 安排执行；不允许下发任意命令。旧版探针会先收到升级指令，升级成功后才能执行电源指令。电源指令两分钟内未被领取会过期，不会在节点很久之后重新上线时意外执行。关机后面板无法远程开机，请确认有其他开机方式。启用远程电源操作前，请先为面板配置 HTTPS 并妥善保管管理令牌。

## 卸载探针

点击面板右上角“安装探针”，弹窗中同时提供安装与卸载命令。卸载完成后，可以在面板中删除对应的离线记录。

也可以直接点击服务器行的删除按钮，确认后移除面板记录，同时将卸载指令持久保存。在线探针在下一次上报时收到指令；离线探针在恢复连接后执行。指令未执行前不会重新注册到列表。

v0.7.0 起探针支持远程卸载：清理 `tz-agent` 服务、`/usr/local/bin/tz-agent` 和 `/etc/tz-agent.env`。旧版探针先接收升级指令，升级成功后再卸载，因此需要节点能够下载 GitHub Release。提示“已排队”不代表机器已完成卸载。卸载后重新安装会生成新的节点 ID。

## 配置

| 环境变量 | 用途 | 默认值 |
| --- | --- | --- |
| `TZ_ADMIN_TOKEN` | 面板管理令牌 | 未设置时启动日志生成临时令牌 |
| `TZ_LISTEN` | 面板监听地址 | `:876` |
| `TZ_DATA` | 数据文件路径 | `/var/lib/tz/data.json` |
| `TZ_PANEL_URL` | 探针连接的面板地址 | 必填 |
| `TZ_AGENT_TOKEN` | 每台服务器的独立探针令牌 | 必填 |
