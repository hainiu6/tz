# TZ Linux 探针面板

一个轻量、自托管的 Linux 服务器监控面板。面板和探针均为单文件程序，无需外部数据库。

## 功能

- 服务器名称、IP、运行时间、CPU、内存、存储实时状态
- 实时上传/下载速度（M/s）、今日和昨日流量汇总、各节点累计上传/下载流量
- 全局流量汇总、在线/离线状态
- 服务器编辑、删除、自定义排序（数字越大越靠前）
- 自定义分组，同一服务器可同时属于多个分组
- 探针一键安装、面板内一键升级
- 所有节点共用一条安装命令，首次上报自动注册
- amd64、arm64、armv7 Linux 支持
- 管理接口令牌保护、探针独立随机令牌
- 登录后可修改管理令牌，修改结果持久保存
- 管理令牌只要求非空，不限制长度、复杂度，支持中文、空格和符号
- 分组编辑支持服务器多选和一键全选
- 运行时间保留到小时，离线时间显示在运行时间下方；流量位于运行时间之前
- 离线节点整行灰显；手机端自动切换服务器卡片，支持直接编辑、升级、删除

## 部署面板

### 离线安装或升级（无需 Docker、GitHub）

保存 `tz-offline-linux.tar.gz` 到本地，上传到面板服务器后以 root 解压安装：

```bash
mkdir -p /root/tz-offline
tar -xzf tz-offline-linux.tar.gz -C /root/tz-offline
bash /root/tz-offline/install-panel.sh
```

安装包包含 amd64/arm64 面板、amd64/arm64/armv7 探针、安装脚本及 SHA-256 校验文件。安装时仅使用解压目录里的文件，不访问 GitHub，不需要 Go 或 Docker。已有数据、管理令牌、节点 ID 和监听端口会保留。请在服务器防火墙放行 TCP 876，并备份离线包、`/etc/tz-panel.env` 和 `/var/lib/tz/data.json`。

已部署的面板也可作为其他面板的安装源，例如从本机面板下载或克隆当前版本：

```bash
curl -fsSL http://面板IP:876/install-panel.sh | sudo bash -s -- --url http://面板IP:876
```

这条命令使用指定面板的 `/downloads/`，不会查询 GitHub；安装更新版本时，请上传新离线包再运行其中的脚本。需要查看管理令牌时，在面板服务器运行：

```bash
grep '^TZ_ADMIN_TOKEN=' /etc/tz-panel.env
```

令牌可能以双引号包裹保存，最外层引号不是令牌内容。升级会保留当前令牌。

### Docker Compose（推荐）

```bash
git clone https://github.com/hainiu6/tz.git
cd tz
# 请先修改 docker-compose.yml 中的 TZ_ADMIN_TOKEN
docker compose up -d
```

打开 `http://服务器IP:876`，输入你设置的管理令牌。

### 直接运行

从保存的离线包中取出对应架构的 `tz-panel-linux-*`，然后运行（探针已内置到面板程序）：

```bash
chmod +x tz-panel-linux-amd64
TZ_ADMIN_TOKEN='替换为高强度令牌' TZ_LISTEN=':876' TZ_DATA='./data/data.json' ./tz-panel-linux-amd64
```

生产环境建议在面板前配置 HTTPS 反向代理。

## 升级面板与修改端口

上传新离线包，解压后执行其中的安装脚本即可升级。新安装默认使用 **876**；已有安装保留 `/etc/tz-panel.env` 中的端口，避免现有探针断连。显式切换到 876：

```bash
bash /root/tz-offline/install-panel.sh --port 876
```

切换前请放行 TCP 876。切换后访问 `http://服务器IP:876`，在每台节点重新执行新面板中显示的安装命令，以更新上报地址；节点 ID 会保留。通过反向代理接入且外部地址不变时，只需更新代理的后端端口。

直接运行程序时，Linux 的低端口需要 root 权限或 `CAP_NET_BIND_SERVICE`；一键安装已为服务配置该权限，Docker Compose 已配置容器内低端口监听。

## 今日与昨日流量统计

列表显示每台服务器的「今日上传」「今日下载」。顶部使用三张卡片：实时上传/下载速度、今日上传/下载总流量、昨日上传/下载总流量。实时速度卡片底部同时显示当前范围内的累计上传和下载总流量。三张卡片均随分组切换：选择「全部服务器」时汇总全部节点，选择分组时只统计该分组。速度只统计在线节点，今日、昨日和累计流量包含该分组的离线节点，同一节点只计一次。左侧分组栏分割线下显示当前范围的在线、离线数量。按北京时间（UTC+8）每天 00:00 将今日数据结转到昨日，面板重启后保留。

统计从首次上报建立基线开始，不把节点此前累计流量算入今日。v0.9.0 修复了上报延迟被误判为重启、计数下降后重复累加历史流量的问题。建议同步升级探针：新版上报启动标识、网卡名称及接口编号，重启或网卡集合变化时重新建立基线，跳过无法确认的那一次增量。暂时下降的计数保留原高水位，恢复后只统计超过高水位的增量；无法识别的网卡计数重置可能少计，直到计数超过原高水位或启动/网卡标识变化。

跨零点的上报间隔按时间比例分配到今日和昨日，长时间断连跨日时属于估算；断连期间丢失的计数无法恢复。升级保留已有数据，不自动清空可能已受旧版 bug 影响的统计；已经多计的流量无法从现有快照准确还原。没有保存的昨日历史显示为 0，从新版运行后的零点开始正常结转。

## 安装探针

进入面板，点击“安装探针”，复制弹窗中的通用安装命令，在所有目标 Linux 服务器以 root 用户执行即可。每台服务器会生成自己的节点 ID，首次上报后自动出现在列表中，无需提前添加服务器。v0.25.0 起安装脚本和探针安装包均由面板直接提供，节点不再访问 GitHub。面板程序内置三种 Linux 架构探针，下载地址为 `/downloads/tz-agent-linux-amd64`、`/downloads/tz-agent-linux-arm64`、`/downloads/tz-agent-linux-armv7`；脚本会先验证 `/downloads/checksums.txt`，校验失败不替换已有探针。

## 华为云 DDNS 定时解析

点击面板顶部的 **DDNS**。先填写华为云的 Access Key Id 和 Secret Access Key，再新建解析任务：填写完整解析域名、A 记录的 IPv4 目标或 CNAME 目标域名，并选择首次执行的北京时间。可设为仅一次、每天、每周或每月；任务也可立即执行，手动执行不改变原定计划。支持编辑、暂停、开启、删除和查看执行日志。日志显示执行时间、原解析值、新解析值和执行结果。删除任务不会删除华为云上的 DNS 记录。

面板会自动在此账号的公网域名中查找所属域名；若记录不存在会创建，若目标已相同则不重复修改。请确保密钥具备 DNS 公网域名和记录集的查询、创建、修改权限。密钥保存在面板服务器的 `TZ_DATA` 数据文件（文件权限 `0600`）中，不会回显到浏览器或写入执行日志。建议为此用途创建最小权限的独立凭据，并使用 HTTPS 访问面板。

## 升级探针

编辑服务器时可以勾选「流量已用完」，列表的流量列会显示红色标记，替代自动计算的剩余值；未填写流量额度也可以标记。取消勾选后恢复原来的剩余流量显示。该标记独立保存，刷新、重启、节点上报或清空流量统计都不会自动取消，不修改实际流量统计，也不会停止或限制节点。

列表的「流量」列分两行显示：上面为较小字号的手动套餐流量，单位为淡灰色；下面为「剩 数值 单位」，仅数值为黄色并放大，「剩」和单位为较小的淡灰色文字（填写流量减去总上传，按 1 TB = 1024 GB 换算，超额时显示负数）。到期时间下方的剩余天数也仅放大数字，文字仍为淡灰色。在服务器编辑弹窗输入非负数值（支持小数）并选择 B、KB、MB、GB、TB 或 PB，默认单位为 TB，例如 `500 GB`、`1.5 TB`；留空即可清除此项，不再计算剩余流量。此项单独保存，刷新、面板重启和节点上报都不会覆盖；「清空流量」只清空统计，不会清除此手填值，剩余值会随总上传重新计算。该列也支持隐藏和拖动排序。

编辑服务器时可在普通文本框手动填写或清空「到期时间」，支持 `YYYY-MM-DD`、`YYYY-MM-DD HH:mm`，无需秒数，按北京时间保存和显示，仅填写日期时按当天 00:00 保存。列表第一行显示到期时间（精确到分钟），下方单独显示剩余时间，仅数字为黄色，文字和单位为淡灰色，亮色主题的数字使用深金黄色，未填写则留空。剩余时间不少于 48 小时时按完整天数计算，少于 48 小时时按完整小时数显示（例如「剩 36 小时」），不足一小时显示「剩不足 1 小时」，已过期以淡灰色显示「已到期」；距离到期不足 48 小时时，到期日期仍标红，并随面板刷新更新。离线时间移至运行时间下方，直接显示具体日期时间（北京时间，依据最后一次上报记录），不再通过鼠标悬停浮窗显示。运行时间、到期时间两列均支持隐藏和调换位置。列表、顶部卡片及测速弹窗中的流量和速度单位统一以淡灰色弱化显示；服务器 IP 放大并提亮，点击名称/IP 仍可复制完整 IP。

服务器行的操作区显示编辑和三点按钮。点击三点可选择测速、升级探针、重启、关机、清空流量或删除服务器。列表增加「前天上传」「前天下载」，支持点击排序和在列设置里显示、隐藏、调整顺序。

### 节点测速

首次启用测速时，先升级面板和探针（顶部「全部升级」或对应节点的「升级探针」），等待节点重新上线。点击节点三点菜单的「测速」打开弹窗，弹窗同时显示该节点当前实时上传、下载速度，随监控上报自动刷新，并与测速结果分区显示；离线时实时速度显示「—」。点击「开始测速」后直接执行，不再弹出二次确认，流量消耗提示仍保留在弹窗内。结果自动回显，包含上传、下载速度、完成时间和失败提示；关闭弹窗不影响测试，可再次打开查看该节点最近一次结果。每节点同时只允许一个任务，两次发起至少间隔 1 分钟；超过 2 分钟未返回结果会显示超时。

测速由节点直接访问 [Cloudflare 官方测速端点](https://github.com/cloudflare/speedtest)，不是浏览器或面板机器测速。使用固定 HTTPS 端点，仅传输随机测试数据，Cloudflare 会看到节点出口 IP，不发送节点文件、探针令牌或管理令牌。每个方向最长 8 秒、最多 64 MiB 有效载荷，两方向最多约 128 MiB（另有协议开销），最多 4 个并发连接，不需要安装 speedtest-cli。测速会占用业务带宽，正常计入今日和累计流量，不会自动取消「流量已用完」标记。结果为该节点到 Cloudflare 路径的 HTTP 吞吐量参考，显示单位沿用面板的 `M/s`（Mbps，字节/秒乘以 8 后除以 1,000,000），并非网卡或套餐带宽的保证值；连接失败时显示错误，不填充虚假结果。

「清空流量」需确认后执行，只清空该节点的今日、昨日、前天及累计上传/下载，不影响其他节点、分组、备注和在线状态。结果持久保存，面板重启后不会恢复。节点下一次上报先建立新基线（离线节点重新上线时同样如此），之后才统计新增流量；清空后累计流量表示从新基线开始的流量，节点重启不会清掉这个累计值。

点击服务器行末尾的三点菜单，选择“升级探针”。在线探针会在下一次心跳收到升级指令，从当前面板的 `/downloads/` 下载与该面板配套的探针，校验 SHA-256 后自动重启，不访问 GitHub。要发布新探针，先升级面板，再点击「全部升级」。

列表顶部的“全部升级”会给面板中的所有节点排队升级，包括离线节点；离线节点重新上线后执行。

## 远程重启和关机

服务器列表的“操作”列提供“重启”和“关机”按钮。确认后，面板只向当前在线节点下发预定义的重启或关机指令，探针在下一次心跳领取并通过 systemd 安排执行；不允许下发任意命令。旧版探针会先收到升级指令，升级成功后才能执行电源指令。电源指令两分钟内未被领取会过期，不会在节点很久之后重新上线时意外执行。关机后面板无法远程开机，请确认有其他开机方式。启用远程电源操作前，请先为面板配置 HTTPS 并妥善保管管理令牌。

## 卸载探针

点击面板右上角“安装探针”，弹窗中同时提供安装与卸载命令。卸载完成后，可以在面板中删除对应的离线记录。

也可以直接点击服务器行的删除按钮，确认后移除面板记录，同时将卸载指令持久保存。在线探针在下一次上报时收到指令；离线探针在恢复连接后执行。指令未执行前不会重新注册到列表。

v0.7.0 起探针支持远程卸载：清理 `tz-agent` 服务、`/usr/local/bin/tz-agent` 和 `/etc/tz-agent.env`。旧版探针先接收升级指令，升级成功后再卸载，因此需要节点能够访问当前面板的 `/downloads/`。提示“已排队”不代表机器已完成卸载。卸载后重新安装会生成新的节点 ID。

## 配置

| 环境变量 | 用途 | 默认值 |
| --- | --- | --- |
| `TZ_ADMIN_TOKEN` | 面板管理令牌 | 未设置时启动日志生成临时令牌 |
| `TZ_LISTEN` | 面板监听地址 | `:876` |
| `TZ_DATA` | 数据文件路径 | `/var/lib/tz/data.json` |
| `TZ_DOWNLOAD_DIR` | 面板安装包文件目录，供同架构或跨架构面板克隆使用；探针使用内置文件 | `TZ_DATA` 同目录下的 `downloads` |
| `TZ_PANEL_URL` | 探针连接的面板地址 | 必填 |
| `TZ_AGENT_TOKEN` | 每台服务器的独立探针令牌 | 必填 |
